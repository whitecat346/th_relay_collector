  # relay-tool 使用手册

从**首次自动收集** → **TUI 纠错** → **保存归档** 的完整流程。

---

## 0. 三分钟上手

```powershell
# ① 定义入口（每次开新窗口都要设一次）
$exe = "D:\东方接力收集\relay-tool\publish\jieli.exe"

# ② 收集：把话题链接丢给它（第一次会慢一点）
& $exe --pipeline "https://www.bilibili.com/v/topic/detail?topic_id=1348289"

# ③ 纠错：进 TUI 逐条看，确认或修正
& $exe --review 1348289

# ④ 保存：填宣传信息，然后产出归档
notepad "D:\东方接力收集\relay-tool\work\1348289\meta.yml"
& $exe --render 1348289
```

做完这四步，`D:\东方接力收集\<slug>\` 下就会出现 `<slug>.csv` 和 `<slug>.md`，与你既有的 22 个归档格式完全一致。

## 1. 这个工具做什么、不做什么

### 它做

| 步骤 | 自动完成的事 |
|---|---|
| 收集 | 免登录抓取话题下**全部**动态（含翻页），提取正文、作者 UID、发布时间、作品链接 |
| 解析 | 从正文里认出**棒号、时段、上一棒/下一棒、代发关系**（支持 8 种实测写法，含中文数字 `第六棒`） |
| 校验 | 找出**缺棒、棒号重复、时段错标、创作者没被正确 @ 出**等问题 |
| 汇总 | 遇到主办方的**总结名册**时，用名册直接对齐「时段 → 创作者 → 作品链接」 |
| 产出 | 生成 CSV（UTF-8+BOM，Excel 双击不乱码）+ 三段式 Markdown + 只读审阅报告 |

### 它不做（**必须你做**）

| 只有人能判断的事 | 工具的处理 |
|---|---|
| 某条动态**算不算这个接力的一棒** | 列进"待确认"，等你按 `Enter` 或 `X` |
| 正文写错/没写棒号 | 列进"待确认"，等你按 `B` 填棒号 |
| 谁是**原作者**、谁是**代发者** | 给出推测 + 理由，等你按 `U`/`P` 确认 |
| 作品**类型**（插画/MMD/手书…） | 只给粗标签（插画/视频/文章），等你按 `K` 细化 |
| 主催是谁、宣传链接是什么 | **完全不猜**，等你在 `meta.yml` 里填 |

> **设计原则**：工具**拒绝**在有人工未确认项时产出最终归档。理由是接力数据的歧义率很高（实测 683 行里类型有 28 种写法，59 行含 N/A，棒号标注错误很常见）。你随时可以用 `--allow-unconfirmed` 强行产出，但那样得到的归档可能不完整。

## 2. 准备工作

### 2.1 找到你的工作目录

工具会自动向上查找含 `ai_guild.md` 的目录作为工作目录。你的工作目录就是：

```
D:\东方接力收集\
```

如果自动查找失败，或你想在别处工作，显式指定：

```powershell
& $exe --root "D:\东方接力收集" ...
```

### 2.2 确认 exe 存在

```powershell
Test-Path "D:\东方接力收集\relay-tool\publish\jieli.exe"    # 应输出 True
```

如果没有，自己发布一次（需要联网）：

```powershell
pwsh -File "D:\东方接力收集\relay-tool\publish.ps1"
```

### 2.3 确认网络可用（仅"收集"步骤需要）

`--pipeline` / `--collect` 需要访问 `api.bilibili.com`。其余所有命令（`--review` / `--render` / `--parse` / `--roster` / `--backfill` / 无参数）**全部离线**。

若收集时报 `安全包中没有可用的凭证` 或 `SEC_E_NO_CREDENTIALS`，见「第 7 节 疑难排查」。

### 2.4 怎么拿到话题链接

在 B站 打开接力活动的话题页，地址栏形如：

```
https://www.bilibili.com/v/topic/detail?topic_id=1348289&topic_name=...
```

**只要里面还有 `topic_id=1348289` 这一段就行**，后面的 `topic_name` 可以不要。工具也接受裸数字 `1348289`。

> 你也可以用话题名搜索，但**不要用 `www.bilibili.com/v/topic/name/...` 这种短链**——它里面的数字不是 topic_id。请用 `topic/detail?topic_id=` 形式。

## 3. 第①步：自动收集

### 3.1 一条命令跑完

```powershell
& $exe --pipeline 1348289
```

它会依次做三件事，并把进度打给你看：

```
【1/3】采集话题
  话题：凤栖白泽庭竹林组24h  (id=1348289)
  接口声称 dynamics=36  discuss=...  view=...
    第 1 页：本页 20 条，累计去重后 20 条，has_more=true
    第 2 页：本页 16 条，累计去重后 36 条，has_more=false
  断言1通过：抓到 36 条 == 接口声称 36 条
  正文覆盖：36/36 条卡片取到文本
【2/3】解析与交叉校验
  话题标签 凤栖白泽庭竹林组24h
  总结名册 opus/1252295159371005957（30 个棒位）
  有棒号/EX 29   无法归属 7   含冲突 6
【3/3】写 review.jsonl
  D:\东方接力收集\relay-tool\work\1348289\review.jsonl  (49,757 字节)
```

### 3.2 怎么读这些输出

| 输出 | 含义 | 要不要管 |
|---|---|---|
| `断言1通过：抓到 N 条 == 接口声称 N 条` | 数据抓全了 | 不用管 |
| `⚠ 断言1未通过：抓到 44 条，接口声称 45 条（差 -1）` | 有动态被删除/隐藏 | **正常**，继续 |
| `总结名册 opus/…（30 个棒位）` | 找到了主办方的完整名册 | **好消息**，棒号会很准 |
| `总结名册 未找到（退回逐棒解析）` | 该活动没有名册 | **正常**，靠逐棒正文推 |
| `有棒号/EX 29` | 29 条认出了棒号 | 剩下的进待确认 |
| `无法归属 7` | 7 条认不出棒号 | 进 TUI 处理 |
| `✗ 棒号缺失（1..30）：第26棒` | 缺第 26 棒 | **常见**。可能是真缺棒，也可能前一条没 @ 出作者 |
| `采集中止（硬失败）` | 数据源异常（游标不推进等） | **要管**，重新跑；持续失败就手动保存页面 |

### 3.3 分步执行（想看清楚每一步时）

```powershell
& $exe --collect 1348289     # 只抓取，把原始数据落盘到 work/1348289/
& $exe --parse   1348289     # 只解析校验，打印完整棒表（离线，可反复跑）
& $exe --roster  1348289     # 只看总结名册抽得对不对（离线）
```

`--parse` 会打印一张完整棒表，这在你想快速看看"这个活动认出来多少"时很有用：

```
  棒     时段     发布时刻              偏差       发布者              创作者              状态
  1     0:00   10-01 00:00:23    +0m      可燃冰块         可燃冰块         ok
  5     4:00   10-01 04:00:00    +0m      沐南沐南沐南     poomi            代发
  18    14:30  10-01 17:42:35    +193m    龙胆紫苑         龙胆紫苑         时段可疑
  ?     -      10-01 10:48:40    -        门前毛豆xiaodm   门前毛豆xiaodm   无法归属/冲突
```

### 3.4 ⚠ 一个必须知道的坑

**`--pipeline` 会重新生成 `review.jsonl`，覆盖你在 TUI 里做过的所有确认。**

所以顺序必须是：**先收集 → 再纠错 → 再保存**。如果你已经纠错到一半想重新收集，先备份：

```powershell
Copy-Item "D:\东方接力收集\relay-tool\work\1348289\review.jsonl" "$env:TEMP\review_backup.jsonl"
```

### 3.5 批量收集

目前没有"一次跑 N 个活动"的批处理入口，需要逐个跑。想批量就写个循环：

```powershell
$ids = @(1343535, 1343333, 1348289)
foreach ($id in $ids) {
    Write-Host "===== $id ====="
    & $exe --pipeline $id
}
```

### 3.6 接力**没有建话题**时：从一个链接开始（`--link` 链遍历，推荐）

有些接力主办方没有创建 B站话题，只发了一条动态，靠各棒之间互相 `@` 出**下一棒是谁**，
再由工具去那个人的空间里找对应那一棒的帖子。给一个链接就能双向铺开：

```powershell
& $exe --link "https://www.bilibili.com/opus/1236672288886095909"
```

它做的事（**和你手动找的思路一样**）：

| 步骤 | 工具怎么做 |
|---|---|
| ① 认出入口 | 自动嗅探链接类型：`opus/<id>`（动态/专栏）、`t.bilibili.com/<id>`（动态）、`video/BV…`（视频）、话题链接；不支持 `b23.tv` 短链与 `read/cv`（请先在浏览器里展开） |
| ② 读这一棒 | 按类型取正文：专栏/动态读 `opus` 页，**视频读简介 + 评论区**；从正文和评论里抽棒号、时段、上一棒、下一棒、代发 |
| ③ 认人 | 把 `@名字` 解析成 uid（`@` 组件自带 uid；手打的用搜索按昵称找，容忍错字/异体字/改名） |
| ④ 找那一棒 | 先翻对方空间动态（`opus/feed/space`），不行再搜文章、搜视频；命中条件 = **对方帖里反向 @ 回你** 或 **发布时间落在该棒时段 ±90 分钟** |
| ⑤ 双向铺开 | 同时向前（上一棒）和向后（下一棒）走，走到"看起来是最后一棒"、两向相遇、或连续两次失败为止 |
| ⑥ 产出 | `work/<slug>/` 下 `chain.json`（链条+审计）、`review.jsonl`（人工确认）、`report.md`（缺口清单） |

常见参数：

```powershell
& $exe --link "<链接>" --date 2025-08-15      # 活动日期（入口帖说不清时用；也可写 8-15）
& $exe --link "<链接>" --hours 32             # 活动时长（默认 24；32h/48h 接力要写）
& $exe --link "<链接>" --as 2025_魅魔日接力_8-15   # 指定输出目录名，不指定则按活动名自动命名
& $exe --link "<链接>" --add-link "<另一棒链接>"   # 补充链接（可给多次），从这些位置继续双向递推
& $exe --link "<链接>" --add-link "<链接>" --at-bar 6   # 链接里看不出棒号时，人工指定它是第 6 棒
```

跑完会打印一行汇总，例如：

```
  节点数       : 8（其中拿到事实 8 条）
  缺口         : 2 处
  请求数       : 183
→ 接着跑：jieli --review e2e_meimo
```

#### 补不齐的时候（这是设计内的流程，不是失败）

`report.md` 里有一份**缺口清单**，每条都带原因、已试过的手段，以及可以直接复制的补录命令：

```
#1 向前 · 邻居未定位 · 期望 @雾雨梦灵(uid=228026390) · 第 6 棒 12:00 · 断在 1236657690311131138
   原因：空间动态 100 条内无匹配；文章搜索空；视频搜索被风控挑战
   补：jieli --link https://www.bilibili.com/opus/1236672288886095909 --add-link "<你找到的第6棒链接>"
```

你在浏览器里找到那一棒的链接后，把 `--add-link` 那行复制出来跑一遍即可；
也可以直接进 TUI 按 **`A`** 粘贴链接（见 4.2 按键表）。

#### AI 辅助（可选，默认关）

`@名字` 手打错字、昵称与账号对不上这类情况，纯规则判定会放弃。想让模型帮忙看一眼：

```powershell
# 1) 先建配置（OpenAI 兼容接口）
Copy-Item .\ai.yml.example .\ai.yml    # 填 base_url / api_key / model；ai.yml 已在 .gitignore 里
# 2) 需要时才开，且每次调用都会问你
& $exe --link "<链接>" --ai
& $exe --link "<链接>" --ai --ai-yes --ai-budget 10   # 免确认 + 最多 10 次
```

它**只发**片段（剥掉 HTML、截断）、候选 uid/昵称、期望的棒号时段，不发整页 HTML；
每次调用的问答都会追加到 `work/ai-log.jsonl`。

#### ⚠ 链遍历的已知局限

1. **搜索接口会风控。** 实测连续请求后，搜索类接口会返回 `code=0` + `v_voucher`
   （不是"没搜到"，是被挑战了）。工具会如实报 `触发风控挑战 v_voucher`，
   此时**该棒只能人工补链接**；隔一段时间再跑通常就恢复了。
2. **视频棒最容易漏。** 一棒如果是**视频投稿**，棒号往往写在简介或评论里，
   而视频搜索最容易被风控挡住 —— 这正是最容易出缺口的地方。
3. **改名/换号会被当成不同的人。** 帖子里 `@` 的是旧号、真正发帖的是新号时，
   工具会用"标题含活动名、还没被认领"的候选兜底，但需要你在 TUI 里确认。
4. **一人多棒**的接法（同一个人发两条）靠"反向 @ + 时间窗"区分，也可能认错，请核对。
5. 棒数是**声明优先、推算次之、都没有才 N/A**；推算出来的会在 `report.md` 里标「棒号推算」。

#### 旧版：`--opus` 单链接模式（保留但不推荐）

`--opus` 只会**顺着正文里的 opus 链接**往下走。实测多数接力帖只写 `下一棒 @某人`
而 `@` 不带链接，所以它经常只拿到 1 条。除非你确认帖子里是贴了链接的，否则请用 `--link`。

```powershell
& $exe --opus "https://www.bilibili.com/opus/1254218608972660737"   # 老路径
```

### 4.1 进入

```powershell
& $exe --review 1348289
```

你会看到这样的界面：

```

待确认 36  已确认 0  已忽略 0  共 36 条  [显示全部]

    1 0:00   御宫樱寻喵         ok         名册作品链接匹配
    2 1:00   简遗w              ok         名册作品链接匹配
    3 2:00   鴉CORVUS           代发       名册作品链接匹配

    9 7:00   少鹅e              ok         HH:MM(标题)
    ? -      R48                无法归属   HH:MM@名字
    ? -      少鹅e              无法归属   该创作者在名册里有 2 个棒位…
────────────────────────────────────────────────────────────────
第 1 棒  0:00  御宫樱寻喵

```

界面分四块：
1. **顶部统计**：待确认 / 已确认 / 已忽略 / 总数，以及当前过滤模式
2. **断言回执**：`有棒号 29 缺棒 1 未归属 6` —— 你每改一条它会**立即重算**
3. **列表**：按棒号排序；`?` 表示还没认出棒号
4. **详情面板**：当前条的完整信息 + **正文原文**（判断的依据）
5. **底栏**：按键提示；有未保存改动时会显示 `● 有未保存改动（按 S 保存）`

### 4.2 按键总表

| 按键 | 作用 | 什么时候用 |
|---|---|---|
| `↑` `↓` | 上下选择 | 一直 |
| `PgUp` `PgDn` | 翻 10 条 | 条目多时 |
| `Home` `End` | 跳到首/末 | 一直 |
| **`Enter`** | **确认这一条**（认可工具的判断） | 看着没问题就按 |
| **`X`** | **忽略这一条**（判定它不是一棒） | 陪跑、无关投稿、重复的说明条 |
| `R` | 撤销本条（回到未确认） | 按错了 |
| **`B`** | **改棒号** | 状态是"无法归属"但你能确定它是第几棒 |
| **`T`** | 改时段 | 时段写错或没解析出来 |
| **`U`** | 改创作者 | 创作者认错了（比如认成了代发者） |
| **`K`** | 改作品类型 | 从"插画"细化为"MMD""手书""COS"等 |
| **`P`** | 改代发者（留空=非代发） | 代发判断错了 |
| **`N`** | 写备注 | 记下"为什么这么判断" |
| **`D`** | 在浏览器打开这条的作品链接 | **核对时的主力**，跳过去看原帖 |
| **`A`** | **粘一个链接补进来**（链遍历模式下用来补缺口） | 手里找到了缺失的那一棒 |
| **`G`** | 看缺口清单（哪个方向、期望谁、第几棒、为什么断） | 想先知道"还缺什么" |
| **`C`** | 看链条视图（棒号/时段/创作者/来源/方向/置信/@ 反指） | 想确认这条链是怎么连起来的 |
| **`S`** | 保存到 `review.jsonl` | 改了几条就存一次 |
| `I` | 切换"只看待确认 / 显示全部" | 想专心处理问题项时 |
| `Esc` `Q` | 返回（有改动会自动保存） | 收工 |

> **编辑按键（`B`/`T`/`U`/`K`/`P`/`N`）的工作方式**：TUI 会暂时退出全屏，在下方显示一行输入提示（如 `棒号（留空=未知）（当前：7）> `），你输入后按回车，TUI 立刻恢复并显示结果。留空表示清空该字段。

### 4.3 推荐的纠错顺序（45 分钟搞定一个活动）

**第 1 遍：先扫"确认没问题"的（最快）**

按 `I` 切到"只看待确认"，从下往上或从上往下，看到状态是 `ok` 的直接 `Enter`。这一步通常能消化掉一半以上。

**第 2 遍：处理"无法归属"**

这类条目的详情面板会告诉你原因，按原因处理：

| 详情面板显示 | 意味着 | 你该做什么 |
|---|---|---|
| `总结名册里没有该创作者的棒位` | 可能是陪跑/无关投稿 | 按 `D` 去原帖看，是陪跑就 `X`，是正片就 `B` 填棒号 |
| `该创作者在名册里有 N 个棒位…无法确定属于哪一棒` | **同人发了多条**（作品条 + 说明条） | 按 `D` 分别看，留下真作品条（`B` 填棒号），另一条 `X` |
| `正文里找不到棒号` | 该帖正文没写棒号 | 按 `D` 去原帖看，或看相邻棒（上一棒/下一棒）推断，然后 `B` |
| `正文只有时段 HH:MM，没有棒号` | 只写了时间 | 按时段在接力里的位置推断棒号，`B` |

**第 3 遍：处理"代发"**

状态是 `代发` 的条目，工具认为**发布者 ≠ 创作者**（通常是主催号代发）。请按 `D` 核对：

- 判断对了 → `Enter`
- 其实不是代发（发布者就是创作者，只是改了名）→ 按 `P` 清空代发者，再 `Enter`
- 创作者名字认错了 → 按 `U` 改

> 你会看到一个规律：**同一个主催号会连续代发很多条**（实测 `沐南沐南沐南` 代发 12 次、`鴉CORVUS` 多次）。工具是靠"这个号代发过 ≥2 次"来识别的，所以只要有几条判断对了，后面会自动跟上。

**第 4 遍：补类型（可选但推荐）**

状态 `ok` 但类型是很粗的"插画/视频/文章"时，如果实际是 MMD、手书、COS、音乐、漫画，按 `K` 改。这一步直接影响归档的可读性。

**第 5 遍：看断言回执**

盯住顶部那行：

```
断言  有棒号 30   缺棒 0   未归属 2
```

- **缺棒数降不下去** → 说明确实有一棒没人发，或那条动态根本不在话题里（去话题页确认）。这是**真缺棒**，可以在最后按 `N` 给相邻条写个备注说明。
- **未归属降不下去** → 剩下的可能真是陪跑内容，按 `X` 忽略掉。

**最后：按 `S` 保存，`Esc` 退出。**

### 4.4 一个真实案例（`1348289` 的 36 条待确认）

| 类别 | 条数 | 处理方式 |
|---|---|---|
| 正常（可一键确认） | 22 | 逐个 `Enter` |
| 代发（需核对原作者） | 7 | 按 `D` 核对，多数 `Enter` |
| 名册里没有该创作者的棒位 | 3 | `D` 看是不是陪跑 → `X` 或 `B` |
| 同人多帖无法定位 | 3 | `D` 比对 → 留一条 `B`，其余 `X` |
| 总结名册卡（不算棒） | 1 | `X` 忽略 |

## 6. 不同场景怎么做

### 场景 A：做一个全新的活动

有话题（绝大多数情况）：

```powershell
& $exe --pipeline "<话题链接>"     # 收集
& $exe --review   <topic_id>       # 纠错（按第 4.3 节的顺序）
& $exe --render   <topic_id>       # 第一次会生成 meta.yml 草稿
notepad "…\work\<topic_id>\meta.yml"
& $exe --render   <topic_id>       # 再渲染一次
```

没有话题（主办方只发了单条动态）：

```powershell
& $exe --opus "<任意一棒的 opus 链接>"   # 会沿链接尽量遍历
& $exe --review opus_<起始id>
& $exe --render opus_<起始id>
```

差别只在第一步的命令；纠错与保存流程完全相同（详见 3.6 节）。

### 场景 B：只想看看某个已有活动的情况（不联网、不改任何东西）

```powershell
& $exe                             # 只读审阅 22 个归档：棒数/缺项/编码/异常
& $exe --slug 2026_大妖精_8-8       # 直接进某个活动的棒表
```

在 TUI 里：`↑/↓` 选活动，`Enter` 看棒表，`PgUp/PgDn` 翻页，`Home/End` 首尾，`Esc`/`Q` 退出。**这个模式绝对不会写文件。**

### 场景 C：某个棒工具死活认不出来

1. 用浏览器打开那条动态页，**滚动到底**（触发按需加载），`Ctrl+S` 保存为 mhtml
2. 把文件放到 `D:\东方接力收集\relay-tool\fixtures\res\`
3. 在 TUI 里按 `D` 打开原帖核对，然后按 `B` 手动填棒号

> 工具当前**不会自动读**你丢进去的 mhtml——那是给解析器做回归测试的夹具。手动这条路的目的是"你自己看清楚"，填数还是靠 `B` 键。

### 场景 D：旧归档格式不一致，想统一

```powershell
& $exe --backfill              # 干跑，只报告不改
```

输出：

```
● 2025_红龙组24h\data.csv
    [编码] GB18030/GBK → UTF-8 (BOM)
    [表头] 第 6 列与第 4 列同名（均为「地址」）—— 历史遗留
    [类型] 插图/图片/绘画 → 插画（与既有 436 行的多数用法一致）（影响 29 行）
汇总：编码 1 个文件 / 重复表头 22 个文件 / 类型归一化 10 个文件（69 行）
```

确认要改就加 `--apply`（**每个文件会先写 `.bak` 备份**）：

```powershell
& $exe --backfill --apply
```

- `--apply` 做两件事：统一编码为 UTF-8+BOM、类型归一化（插图/图片/绘画 → 插画）
- **不会**改表头、不会改文件名、不会动任何语义
- 想连表头也改（把重复的第 6 列「地址」改成「作品链接」）：加 `--fix-header`。**不建议**——你既有的 `csv_md.py` 是按列序读取，功能不受影响，但改完新旧文件表头会不一致

### 场景 E：TUI 状态机自检（怀疑按键不生效时）

```powershell
& $exe --selftest-review 1348289
```

它会用**合成按键**跑一遍 确认 → 忽略 → 保存 → 重新加载，最后报告：

```
④ 落盘核对
   条目总数   36
   已确认     3
   已忽略     1
   ✓ 确认/忽略状态已持久化到 review.jsonl
```

**注意**：这会真的改动 `review.jsonl`（确认 3 条、忽略 1 条）。跑完想恢复就重新 `--parse` 一次。

## 7. 疑难排查

| 现象 | 原因 | 解决 |
|---|---|---|
| `安全包中没有可用的凭证` / `SEC_E_NO_CREDENTIALS` | Windows 无法生成 TLS 临时凭证（受限环境会这样） | 放开对 `%APPDATA%\Microsoft\Crypto\` 的写入；或让该命令以普通权限运行（Python 的 requests 走 OpenSSL 不受影响，可作对照） |
| `找不到工作目录` | 自动查找失败 | 加 `--root "D:\东方接力收集"` |
| `无法从「…」解析出 topic_id` | 链接里没有 `topic_id=` | 用 `topic/detail?topic_id=` 形式的链接，或直接给数字 |
| `采集中止（硬失败）：…游标未推进` | B站 接口行为变了 | 隔一会儿重跑；持续失败就手动保存页面 |
| `没有找到 review.jsonl（先跑 --pipeline ...）` | 还没收集 | 先 `--pipeline <topic_id>` |
| `未找到 meta.yml，已生成草稿` | 首次渲染 | 填 `meta.yml` 后重跑，这是正常的 |
| TUI 里按键没反应 | 你正在输入框里（底栏会显示 `> `） | 输入内容后按回车即返回 |
| TUI 显示错位/花屏 | 终端窗口太窄，或不是 Windows Terminal | 拉宽窗口；用 Windows Terminal（代码页 65001） |
| 汉字在表格里对不齐 | 旧版终端不支持宽字符 | 用 Windows Terminal；工具已按显示宽度计算，只在极旧终端会错位 |
| `could not convert string to float: 'N/A'` | 你在用 `legacy/csv_md.py` 处理含棒数异常的 CSV | 这是那个遗留脚本的限制（它对棒号做 `float()`）。渲染器已把异常行放在文件末尾；用 Excel 或工具本身的 `--render` 即可 |
| Excel 打开 CSV 是乱码 | 文件不是 UTF-8+BOM | 工具产出的都是 BOM 版；若是旧文件，跑 `--backfill --apply` |

## 8. 附录

### 8.1 命令参考

| 命令 | 联网 | 作用 |
|---|---|---|
| `jieli` | 否 | 只读审阅已有归档（默认视图） |
| `jieli --slug <目录名>` | 否 | 直接进某活动的棒表 |
| `jieli --pipeline <id\|链接>` | **是** | 采集 → 解析 → 写 `review.jsonl` |
| **`jieli --link <链接>`** | **是** | **链遍历模式**：给任意一棒（动态/专栏/视频）就双向铺开整条接力；产出 `chain.json` + `review.jsonl` + `report.md` |
| `jieli --link <链接> --add-link <链接> [--at-bar N]` | **是** | 补充链接从该处继续递推；`--at-bar` 用于链接里看不出棒号时人工指定 |
| `jieli --link <链接> --date 2025-08-15 --hours 32 --as <目录名>` | **是** | 覆盖活动日期/时长/输出目录名 |
| `jieli --link <链接> --ai [--ai-yes] [--ai-budget 20]` | **是** | 打开 AI 辅助（默认关；逐次确认；默认上限 20 次） |
| `jieli --opus <opus链接\|opus_id>` | **是** | 旧版单链接模式（只会顺正文里的 opus 链接走，多数接力拿不全，建议改用 `--link`） |
| `jieli --collect <id\|链接>` | **是** | 只采集 |
| `jieli --parse <id>` | 否 | 只解析校验，打印完整棒表 + 重写 `review.jsonl` |
| `jieli --roster <id>` | 否 | 只抽总结名册 |
| `jieli --review <id>` | 否 | **TUI 人工确认**（也接受 `opus_<id>` 与链遍历的 `<slug>`） |
| `jieli --render <id>` | 否 | 产出 CSV + md + 只读报告 |
| `jieli --backfill [--apply]` | 否 | 旧归档零风险回填 |
| `jieli --selftest-chain` | 否 | 链遍历离线自检（链接嗅探 + 遍历器纯逻辑，不联网） |
| `jieli --selftest-review <id>` | 否 | 人工确认状态机自检 |
| `jieli --help` | 否 | 帮助 |

通用开关：

| 开关 | 默认 | 作用 |
|---|---|---|
| `--root <路径>` | 自动查找含 `ai_guild.md` 的上级目录 | 工作区根目录 |
| `--out <路径>` | `<root>\relay-tool\work` | 过程产物目录 |
| `--archive-root <路径>` | `<root>` | 渲染输出根目录 |
| `--plain` / `--dump` | — | 纯文本模式，不重绘、不读键盘（脚本化验收用） |
| `--allow-unconfirmed` | 关 | 跳过"必须人工确认"闸门（不建议） |
| `--fix-header` | 关 | 回填时把第 6 列「地址」改名为「作品链接」（不建议） |

### 8.4 一次完整归档的检查清单

- [ ] `--pipeline` 跑完，看到 `断言1通过` 或理解差额原因
- [ ] `--review` 里**待确认降到 0**（或剩余的都写了 `N` 备注）
- [ ] 断言回执里 `缺棒` 为 0，或每处缺失都有解释
- [ ] 同名多帖的条目已经留一条、忽略其余
- [ ] 代发条目的原作者/代发者核对过
- [ ] 作品类型细化过（MMD/手书/COS/音乐…）
- [ ] **按了 `S` 保存**（底栏不再显示 `● 有未保存改动`）
- [ ] `meta.yml` 填好 `slug`（符合 `{年份}_{活动名}_{月-日}`）、主催、宣传链接
- [ ] `--render` 成功，无"渲染被拒绝"
- [ ] CSV 用 Excel 打开**中文正常**（说明 BOM 正确）
- [ ] md 打开检查 `## 宣传` 段内容对不对
- [ ] `work/<id>/report.md` 里的警告都看过

### 8.5 想撤销改错了的归档？

`--backfill` 只在编码/类型上动过刀（且带 `.bak`）。渲染产出的归档目录如果做坏了，**直接删掉整个活动目录重跑 `--render`** 即可——`meta.yml` 与 `review.jsonl` 都还在 `work/` 里，人工确认的成果不会丢。

**这是本工具最重要的设计**：你的劳动成果（人工确认）存在 `work/<id>/review.jsonl` 里，与归档产物解耦。归档产物是**随时可以重新生成的派生物**。
